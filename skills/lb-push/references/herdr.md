# Herdr 运行约定

本文件仅用于 runtime.adapter=herdr。执行 Herdr 操作前必须读取本文件及环境提供的 Herdr 工具技能，并使用当前接口核实可用参数；未选择此适配器时不要加载其 CLI 细节。授权和执行隔离由 [AGENTS.md](../../../AGENTS.md) 定义。

## 启动与隔离

控制范围为当前工作区和已获授权的会话。业务执行包由所属 Agent 在原仓库下的独立 Git worktree 操作；已完成 worktree 的删除适用根规则中的清理例外；不能让协调者代做跨仓 worktree 设置或业务环境搭建。若缺少能够承担该设置的所属 Agent，报告前置条件，不绕过边界。

执行 Agent 使用不同于协调者主标签页的专用标签页，保留工作目录。创建时使用 `--no-focus`，后台操作必须显式定位 Agent、标签页或窗格。无法避免夺取焦点的操作交人类完成。

本机（local）由 logbook 派发的子 Agent 必须创建在协调者当前的 Herdr workspace。创建 tab 前读取宿主 `SKILL-PARAMS.yaml` 的 `runtime.herdr.workspace_id_env`，取得环境变量实际值并显式传入 `--workspace <值>`；缺失且只读核实无法补齐时咨询人类，不依赖 TUI 当前焦点。同一仓库通常只保留一个适用的 Agent session，连续工作包优先恢复并复用它；不得为每个任务重复创建 session。只有独立检查需要实施者隔离、现有上下文或模型/数据边界不再适用，或用户批准的并行批次确需独立执行者时才另建，并在交接中记录理由。复用前仍须核对实际模型、部署、工作目录、未结责任和当前任务是否兼容。

凡 logbook 创建的 Herdr named session、tab label 与 pane label，使用宿主 `SKILL-PARAMS.yaml` 的 `runtime.herdr.label_prefix`；执行、监控和临时门禁窗格均适用。创建后立即核对实际 label，命名失败就修正原资源，不复制出一个同用途资源。Herdr Agent identifier 受工具自身格式限制，不强加标签前缀；仍使用稳定、唯一且可定位的 Agent 名。

人类需要查看的 Agent 可保留状态标记。内部基础设施若需隔离可见性，应在已授权的独立工作区或命名会话中运行；不要因为清空名字就假定隐藏状态。缺少必要布局时报告阻塞，不能塞入主窗格。每个执行包的可见监控仍须满足根规则。

启动选择见 宿主 `.agents/lb.yaml`，用户明确选择只在候选范围内生效。先按敏感性过滤，再按任务需求选择模型；记录方案与部署依据。按 [配置契约](../../../docs/configuration.md) 解析本轮 runtime 参数；配置不授权其他仓库、发布或修改。默认包装命令不能据名字推断引擎或权限，必须检查实际进程。

派发执行 Agent 使用宿主 `.agents/lb.yaml` 声明的完整包装命令及参数，不以 `herdr agent start --kind` 的通用引擎替代。包装器若为 shell 函数，按 `runtime.herdr.shell` 在目标交互 shell 中核实其存在，再按当前 Herdr 接口启动；找不到就报告缺口。启动后核实实际模型和部署归属，再命名、交包及监听。删除已完成 worktree 时，可选择已声明的无工作树启动方案；不借此授权删除分支、fetch 或其他 Git 管理操作。

仓库信任门按根规则由协调者处理：弹窗路径核对为 logbook 已登记、当前任务已授权的仓库或其合法 worktree 后，默认接受 workspace trust，再重试原包装启动方案；未登记或不明路径不得自动接受。信任通过只解除启动门禁，不等于业务包已接收，也不扩大登录或审批权限。

## 权限模式

是否使用自动放行以宿主规则和 `runtime.herdr.permission_mode` 为准；缺少明确授权或参数时咨询人类，不自行选择放行模式。这不允许泄露秘密、破坏性数据操作、跨范围访问，或未经授权的提交、推送、合并和发布；不得借更换 Agent 规避上层限制或真实身份审批。

- 恢复时仍使用选定包装方案并核对会话身份，不以裸引擎命令绕过模型选择；新会话不要无条件恢复旧上下文。
- 工具支持某个 kind 不代表它在仓库候选范围内。不得把通用引擎示例当作启动方案，或用引擎命令替换选定的包装命令；不得通过附加参数改模型、profile 或部署归属。
- 派发前检查实际模型与所选部署方案一致，并检查进程参数；已获准的权限模式还须有实际状态证据。仅切换 UI 模式不算证据。包装启动器的实际参数缺少证据时，报告未验证，不能假定已满足要求。
- 如果只是启动参数不符合已授权模式，保存交接，在同一专用标签页修正并恢复；不要反复点击单条审批。若遇到真实登录、批准或上层拒绝，直接交人类处理。

持久权限约定有必要时在 thinking 记录一次，临时审批提示不抄进主日志。

## 派发与监听

向 `herdr agent prompt` 提交工作包时，将完整任务文本作为一个字面 argv 参数传入。不得把含 Markdown 反引号、`$()` 或其他 shell 活性内容的文本插入未引用或双引号 shell 命令字符串；优先使用直接接口或能保留字面内容的单引号/argv 传参。存在 shell 改写风险时，提交后读回实际 prompt，逐字核对内容未被执行、展开或截断。

发送前核对目标 workspace、tab/pane、实际会话与输入行；同一 pane 可能切换了主会话和侧会话，名称与 pane ID 不足以证明接收者身份。通知 Captain 必须由其实际主会话确认，侧会话收到或工具返回 agent_prompted 仅证明局部送达。输入行存在未发送残留文本时，`herdr agent prompt` 提交会以本次文本覆盖残留、不拼接——提交与清行一律走 `agent prompt`；`agent send-keys` 的 enter/esc/ctrl+u/backspace 对 codefuse 主输入行不生效，不要用按键提交或清行（2026-10-01 实测）。

目标处于侧会话时，先核实主会话状态、未发送输入及当前界面支持的切换方式；只有在获准控制范围内且不会中断运行、覆盖输入或夺取焦点时才切回，再读回身份并发送。不要固化快捷键，不靠重复发消息猜测送达。侧会话的工具限制不能推广为整个项目无执行能力，也不能通过切换会话绕过限制；不能安全完成时明确报告主会话尚未收悉。日志迁移通知须包含旧/新入口、回传位置、责任不变及写前重读要求，取得主会话确认后记录交接。未发送输入存在、主会话状态未知或控制面已明确禁止时，只能只读核验；禁止通过试按切换或试发消息验证限制，工具拦截也不能替代发送前判断。

提交完整工作包后，确认实际任务文本可见或收到明确确认，再观察 Agent 的真实状态。信任、认证或其他启动门禁不是业务执行；报告具体关口，不以空标签页暗示正在工作。

工作包被接收后，确认执行者所在 workspace 内有独立、可见、只读的监控标签页，使用 Herdr 状态等待机制监听指定 Agent 的 `idle`、`done` 或 `blocked`。模型自行判断新建或复用，恢复与换包时重新确认关联和监听就绪。监控 tab/pane 的 label 同样使用宿主声明的前缀。监听必须关联本次派发，不能把上轮残留空闲当成本轮完成。

监控不进入仓库、不跑业务命令、不取代验收、不答审批。它只让人类看到状态变化与回传位置，再交协调者核验。偶尔查询状态只用于诊断，不能宣称已启动监听。

协调者须核对监听实际运行，并读取本次状态与新输出，不能只创建空标签页。可使用工具当前支持的状态等待，例如 `herdr agent wait <agent-name> --until idle --until done --until blocked --timeout <毫秒>`，单次等待不超过 `limits.wait_seconds × 1000`。已有可见监听结果可供协调者使用，不因 Codex 或 Claude Code 客户端差异强制重复等待。两个实测陷阱：执行者挂着后台任务（轮询/长命令）时其状态会在回合间隙呈 idle——一次 `agent wait` 返回只证明回合结束，不证明完成，完成判据是新的执行输出或明确回传；用 grep 文本匹配 pane 内容做条件监控时会命中 prompt 回显原文——须以"新出现的输出行"等增量签名为条件，或改用状态等待与直接读取。等待到期仅刷新观察，任务停滞与超时按 [执行与恢复](execution.md) 判断。

派发已成功但监听失败时，准确报告部分完成，保留任务和 Agent 标识，修复已授权监控步骤，不重复派发。一次性监听结束后，恢复同一包时重新确认监听就绪。等待使用 limits.wait_seconds，停滞处理按 [执行与恢复](execution.md)，不得虚构未验证的监听命令。

## 保留、恢复与关闭

普通完成后的释放条件：交付物与证据已存档，所需检查通过或明确无需检查，剩余缺口已回传，无未完成责任，且会话上下文不再有继续保留的价值。

工作包完成不强制关闭会话。上下文、连续调查或后续工作仍有价值时保留，记录理由与恢复触发条件；状态使用工具实际支持的值。不要无理由保留，也不要擅自扩大已完成工作包。上一技能（如 lb-preflight）刚在同一仓库做过只读分析、会话仍空闲时，优先复用该会话为执行者：它自带仓库与技能链上下文，派发即接续，无需另起会话或重交背景（复用前照常核对模型、部署与数据边界）。

用户要求终止、清理或资源约束迫使异常关闭时，先保留交接、未完成责任和恢复条件，在授权内关闭；不把异常关闭记为验收完成。管理一组 Agent 不等于管理所有服务，旧服务须确认归属和操作权限。

主动结束执行会话（GC）时注意：执行 Agent 无法对自身 CLI 发送 `/exit` 等用户侧内置命令——它把命令写进回复文本不等于已执行。由协调者发送 `/exit`；输入行已有未发送残留文本时用 `herdr agent prompt` 提交（会覆盖残留），不与 `pane run` 拼串。`-w` 工作树会话退出时弹出「Keep / Remove worktree」确认框，默认预选 Keep：GC 规则要求不删 worktree，核对光标确在 Keep 后再回车；含义不明或预选在 Remove 时不盲确认，Esc 取消交人工。退出前让执行者把交接、未提交改动与恢复条件写清并推送；退出后记录恢复线索（CLI 会在窗格回显 `--worktree <名> --resume` 恢复命令）。产物行指向过该 worktree 内路径时，删除前把产物迁往稳定位置或把产物行改指不可变身份。
