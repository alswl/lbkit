# 推进项目任务

mode 为 advance（推进）、resume（恢复）或 cleanup（清理获准资源）。未限定单项的推进沿已确认清单连续串行执行；明确单项或批次遵守其终点。模式和技能切换不扩大授权。

## 输入与前置条件

每次调用先从磁盘读取目标 logbook，核对目标、非目标、工作目录、完整有序清单、授权与已有回传，不以会话记忆或旧行号代替。必须读取 [配置契约](../../docs/configuration.md)（含协作参数）、[执行与恢复](references/execution.md) 和 [协调契约](../../docs/coordination.md)。缺少本步必需参数且只读核实无法补齐时咨询人类。

新建或替换会话时解析完整 launcher；复用仍须核对实际模型、部署和输入边界。运行操作确定 runtime.adapter 及实际能力；Herdr 控制前读取 [Herdr 适配](references/herdr.md) 和环境工具技能。能力缺失时停止依赖步骤，不绕过包装器、监听或隔离要求。

写入前读取 [日志格式](../../docs/logbook-format.md) 和 [文档适配流程](../lb-update/references/document-adapters.md)。只维护获准清单、状态和简短事实，保留人类目标、大段正文及已有标题文字和编号。

已有待办首行文字不得改写、追加或删减，仅按证据更新复选框状态。任务下只补极简状态、阻塞或产物链接；执行过程、技术细节和详细证据放入对应 Thinking，不堆在主日志子项中。

## 推进闭环

派发、复用及等待回传时检查执行会话上下文占用。超过 80% 自动 GC，无需再次确认：保存工作包、工作树、候选、证据、未结责任与未发送输入，在安全边界结束旧会话，用合规包装器启动新会话接续原工作树并重建监听；不继承整段旧上下文，不等待 `/compact` 代替 GC。无法从旧会话取得交接时，使用已核实日志与磁盘状态恢复，先核对未完成操作，避免重复副作用。保留未提交改动及仍需使用的服务，不删除 worktree，不重置验收或复核次数。占用比例未知时不得猜测；只回收本项目获准管理的执行会话。由 lb-status 转入时仅完成 GC，原任务有继续执行授权才续跑，不派新任务。

浏览器工作交执行 Agent 使用宿主已声明的浏览器工具，采用任务独立的 session；需要固定 profile 时读取 `lbkit-agents.yaml` 的 `browser.profile`，缺失且无法从任务获知时咨询人类。派发与验收时核实浏览器归属，不能仅凭 session 名称判断。不连接或自动接管人类主浏览器，不删除锁或关闭用户窗口；profile 被占用时报告冲突，不强行复用。需登录时由人类在自动化专用浏览器完成。

1. 按 [CLI 读取流程](../lb-update/references/document-adapters.md#本仓-cli-调用) 运行当前日志的 `context --json`，结合原文与授权核实首项；不能只信 `next_task`。advance 选择文档顺序首个未勾选项；resume 核对原包、当前清单与授权。已有同包执行者先恢复，不重复派发；首项阻塞不跳过。计划已由人类确认且输入就绪时主动派发，不停在“可以开始”。新建或重组的计划须满足 lb-plan 准出条件：人类目标已写定，工作目录、Stage 与逐项待办已确认。
2. 核对工作包的结果、范围、输入、负责人、依赖、证据门和必要的有限复核轮数。授权内缺失事实交所属 Agent 调查，范围外信息咨询人类。证据门要求 E2E、真实环境、质量报告或关键步骤截图时不得降级为静态检查；详细证据要求见 [证据模型](../../docs/evidence.md)。
3. 按输入敏感性过滤声明的启动方案，再按任务需求选择模型。敏感或分级未知输入仅用已确认的内部部署；复用、子 Agent、评测同样遵守。通过已选运行适配器在责任仓库派发完整工作包，业务执行使用隔离 worktree。模型与上下文适用时复用会话；需要独立检查或获准并行时分开。协调者不代做跨仓实现或环境设置。
4. 核实完整任务已接收并观察实际运行。接收后通过 CLI `task update --status /` 标 `[/]`，重取 context/token 后以 `sync` 同步阶段状态，执行前预览差异、写后 `check`；信任门禁或空标签页不代表接收。确认有可见只读监听关联本次派发，模型判断新建或复用；监听失败修复原监听，不重复派发。工作区、命名、焦点和安全传参遵守 Herdr 适配。
5. 等待后读取最新状态和输出。`idle`、`done`、`blocked` 触发回传或阻塞核验，不直接勾选；仍 `working` 时用新事实判断进展。单次等待受 limits.wait_seconds 限制；通常连续 10 分钟无有效进展即到停滞极限，按任务特点判断，不能靠重复等待或重启会话拖延。到限核实现场、停止继续尝试并报告，不因等待到期直接杀进程。
6. 执行偏离已确认方案可在原范围内纠正；已确认方案本身方向错误、重大决策、授权外关键信息、登录审批或范围变化时停止并咨询人类。原任务内常规问题自行处理，不能把所属 Agent 可完成的工作退回用户。缺少候选、样本、工具或环境时，不以大量“未知”的部分报告代替原交付；已接收项仍为 `[/]`，按事实记阻塞。
7. 回传必须使用 [lb-update](../lb-update/SKILL.md) 核验并写回，保留已用复核轮数。验收通过后重新读取原文及 `context`，在已有推进授权内继续下一项；明确单项/批次终点、人工关口、严重卡点或全部完成时停止。新建、重排和扩大范围仍须人类决定，不能以连续推进为由越界。

外部发布遵守宿主规则：核对认证身份属于人类负责人，正文采用其判断与口吻，不能把协调或执行 Agent 写成对外责任主体。身份或口径不明时暂停该发布；工具能力缺口不授权换成语义不同的通道。

cleanup 只处理获准资源，不选择业务首项或派发后续任务。已完成 worktree 的删除适用根规则中的例外；会话与监控的复用、保留和清理由模型结合现场判断，不影响其他项目。

## 汇报与交接

关键结果交接按受众选形态：待办事项下的产物行优先人类负责人实际可访问的本地路径，文件在本地不存在或需跨机/对外分享时才用远程 URL。工作项、PR、已发布单页 HTML 等网页型结果仍用 URL，并写入所属阶段的相关链接区。写回前核对链接或路径对应实际存在的交付物；尚未发布或归档的材料如实标明，保留既有证据位置，不把改写路径当作完成归档，也不因这项要求擅自新增发布或归档任务。

报告接收事实、执行者位置（Herdr 名称、workspace、tab/pane）、监听、结果或阻塞，以及下一步谁做什么、何时继续；不报告焦点。运行事实与验收结论分开，没有回传不暗示完成。

需要人类接手时，回复前重读日志以取得准确文件与行号，说明已核实事实、已尝试方法、可选决定及解除条件。登录或审批给出具体系统、对象、页面或会话位置和完成标志；重大决策说明取舍。事实不足时先在授权内补齐，不让用户自行摸索。凡需人类负责人处理而无法推进的计划外事项，把 `🚨` 与阻塞原因、具体操作、解除条件写到事项正文最前面并保持原状态（已接收项 `[/]`，不勾选、不新增或转移任务；人类负责项不得改为执行中）；对话汇报不能代替日志写回。计划中已标 `👱` 的人工待办到关口停下即可，不另标 `🚨`；执行者自处理中的阻塞待其回传，仅在停滞到限或超界时升级为 `🚨`。

无需人类接手时说明所属 Agent 的下一动作与回传条件，并继续授权内工作，不把进度报告变成任务级确认。已到授权终点则明确说明完成范围及下一项，不擅自开始。
